# 微信小程序临时脱敏采集

这是独立的临时诊断工具，不是新的去广告订阅，也不是全量微信抓包。它只在你手动开始后保存最小摘要，不改分流、机场、证书或正式去广告文件，不自动放行已被拦截的请求。当前仅完成离线测试，QX 的实际导入和 iPhone 采样效果尚待真机验证。

## 一键导入入口

[在 iPhone 上打开临时采集任务库](https://quantumult.app/x/open-app/ui?module=gallery&type=task&action=add&content=%5B%22https%3A%2F%2Fraw.githubusercontent.com%2F724-cyber%2Fquantumultx-app-adblock%2Fmain%2Ftools%2Fwechat-capture%2Fgallery.json%22%5D)

用 Safari 打开，允许唤起 Quantumult X。在任务库里添加这组四个任务；“开始新采样”项通过 `addons` 连带添加独立重写资源。这个入口打开任务库供确认，不会跳过 QX 的添加步骤，也不替换整份配置。[官方任务库示例](https://github.com/crossutility/Quantumult-X/blob/master/gallery.json) · [官方导入协议](https://github.com/crossutility/Quantumult-X/blob/master/url-scheme.md)

确认任务和“微信临时脱敏采集”重写资源已下载、启用，资源解析器关闭。已有 `Own-Adblock`、`Own-App-Ads` 和机场资源保持不动。若任务库未自动带入附加资源，可在重写资源列表手动添加：

```text
https://raw.githubusercontent.com/724-cyber/quantumultx-app-adblock/main/tools/wechat-capture/capture.snippet
```

Universal Link 未唤起 App 时，可以复制原生入口：

```text
quantumult-x:///ui?module=gallery&type=task&action=add&content=%5B%22https%3A%2F%2Fraw.githubusercontent.com%2F724-cyber%2Fquantumultx-app-adblock%2Fmain%2Ftools%2Fwechat-capture%2Fgallery.json%22%5D
```

导入本身不会开始采样。四个任务全部是手动 `event-interaction`，没有 cron、后台更新或自动开始任务。

## 手机上怎么用

1. 先把原 QX 配置备份在自己的设备上。保持现有网络、分流和广告规则不变，开启 QX 隧道与重写。
2. 点击任务“微信采集 开始新采样 清空旧采样”。这会替换本工具上一次的本地采样；其他脚本数据不动。
3. 打开目标小程序，正常复现一种广告，再做一次普通业务操作作对照。记下小程序、iOS/微信/QX 版本、广告类型和相对时间。不要同时聊天、支付或进入个人资料页。
4. 返回 QX，点击“微信采集 停止并导出到iCloud”。它先确认本地状态已经停止，再写出脱敏 JSON。
5. 打开 iOS“文件”App，找到 **iCloud Drive → Quantumult X → Data → wechat-capture**，选择最新的 `wx-capture-数字.json`。人工检查后，只把这个 JSON 与操作说明发回分析，不要发整份 QX 日志或配置。
6. 发完后点击“微信采集 清除本地采样”，并停用或删除临时重写资源与四个任务。无需移除原证书、机场或正式订阅。

最多采样 5 分钟、64 条摘要或约 48 KiB 存储，达到任一限制就停止记录。5 分钟按后续请求、状态或导出操作检查，不存在后台定时器；到期后的请求不会继续被加入。请求和响应各算一条，流量繁忙时可能在 5 分钟前就满。

导出到 iCloud 是你点击导出按钮后的显式操作，会通过自己的 iCloud Drive 同步；采样期间只写 QX 的本工具偏好键。若不愿同步到 iCloud，不要点击导出按钮，先停止使用此工具并联系维护者另选导出方式。脚本本身不调用网络上传 API。

若 iCloud 未启用或写文件失败，工具会停止采样，并仅在 QX 脚本日志输出 `WX_CAPTURE_EXPORT_BEGIN` 与 `WX_CAPTURE_EXPORT_END` 之间的脱敏 JSON。只复制这个区块；其他脚本的日志可能含敏感数据，不能分享整份日志。

## 自动脱敏保留什么

| 信息 | 处理方式 |
| --- | --- |
| 候选主机 | 只接受源码里明确列出的精确主机，不匹配整个 qq.com 或任意微信子域 |
| 路径 | 只保留已列入字典的静态段；未知段写成 `[segment]`，数字、标识和任意字符串不会原样导出 |
| 查询参数 | 只保留少量已知广告参数；广告位和 app 标识也遮蔽，未知参数名和值均不保留 |
| 请求头 | 不保存原始请求头；Referer 只变成“符合小程序格式”的布尔值，不记录 appId、版本或原 URL |
| 请求正文 | 不读取、不保存 |
| 响应头 | 仅保留规范化内容类型、编码、状态码与大小区间，不保存 Set-Cookie 等原始头 |
| 响应正文 | 仅在少数已知业务路径尝试保留广告字段的最小 JSON 摘要；二进制、错误格式、非 JSON 和大正文不保存 |
| JSON 内容 | 白名单字段、有限的状态数字、广告枚举及布尔值；未知键名不复制，自由文本、素材 URL、账号与设备标识不保留 |

数组最多取前五项、结构深度有限；未知键只记录数量。嵌套 JSON 字符串也经过同一白名单。输出是有损摘要，不是可以重放的 HAR 或原始响应；不能拿它证明原始字节、精确数组总长、完整业务协议或广告已经被拦截。

自动最小化不等于完全匿名：域名、相对时间、广告状态等仍能透露操作情况，发送前仍需人工检查。采集器不会清洗 QX 自己的原始 HTTP Analyzer 数据，所以**不需要为了此工具开启 HTTP Analyzer**；若另行开启，其原始记录必须单独保护，不能当成本工具的脱敏输出分享。

## 为什么可能导出零条或没有正文

工具**不新增 MITM 主机**，也不会安装证书、关闭上游证书校验、改 UDP/HTTP3 设置，或为采样绕过正式拒绝规则。HTTPS 未被现有 MITM 解密、微信专有/加密通道、直连 IP、已被拒绝的连接、尚未列入候选范围的主机都可能没有记录。它也不读取 QX 原生连接数据库，不能保证归因到微信进程。

默认广一些的请求头观察用于发现候选路径；响应体观察仅限精确的 `js-operatewxdata` 路由及 `addatareport` 业务路径，不广泛缓冲视频、图片或所有微信响应。这些是观察种子，不表示已经证明它们就是当前 iOS 可见的外层 HTTP URL。

若为零，先发回零条 JSON、版本与复现步骤；不要自行加 `*` 或整个微信域名解密，也不要停用全部广告规则。后续有明确候选主机和路径后，再单独评估有限的采样范围。没有正文时不要导出密文或会话密钥。

## 与现有订阅的关系

代码不返回修改过的网络字段，异常也调用 `$done({})`；不改正式资源字节，不移动已有订阅、不写其他脚本的偏好键。不能承诺零开销或与任意第三方重写零冲突：QX 可能按规则优先级选择处理器，本工具无法读取或自动串联其他脚本。已有同范围请求头/响应体重写时先核对；发生异常立即停用本临时资源，不要让它取代业务脚本。

并发请求使用 QX 偏好存储的读改写，缺少跨脚本事务，可能丢失记录；这是有界诊断，不是无损抓包。独立停止键只由控制任务写入，迟到的数据写入不能重新打开采样；导出可能不包含正在结束的请求。停用资源只停止之后的钩子调用，不删除本地摘要。清除按钮只删 `owned.wx-capture.v1` 及其 `.gate` 停止键，不会删已导出的 iCloud 文件。为避免正在结束的脚本留下迟到摘要，停用资源、等待当前请求结束后再清除；导出文件及其“最近删除”由你自行管理。
